# HOI4 AI Operator architecture

Agent → adapter → semantic Observation / Action / Result → MCP or Python API → domain service → deterministic GUI executor → InputBackend → HOI4.

`OperatorAPI.execute(action, arguments)` only accepts semantic method arguments. Coordinates, templates, HWND, PID and Computer Use objects are private executor/backend configuration. `executor/backend.py` defines the current replaceable input boundary; `worker.py` implements the guarded local bridge, and `scripts/computer_use_pump.js` alone imports `@oai/sky`. Domain services do not import that package. No full Agent Adapter or native backend rewrite is included.

For an explicitly attached `--military` runtime, `executor/right_drag.py` wraps the same worker in `NativeRightDragBackend`. Only `right_drag(start, end)` uses public Windows SendInput; capture, clicks, keys and scrolling still delegate to Computer Use. The wrapper shares the existing action guard and transaction lock, requires an exact calibrated capture profile and matching Win32 client dimensions, checks before each input, issues at most one right-down, and releases in finally and on independently observed F12/focus/deadline/watchdog failures. Release failure is surfaced; ownership remains set for cleanup to retry. There is no activation, launch, general held-button API or Agent-facing coordinate interface. The 26 native safety tests remain offline; two independent official SDK offensive actions now prove normal live submission and release.

Existing Research / Focus / factory-count proof remains in its historical reports. New actions use `contracts.py` and `executor/pipeline.py`: fresh telemetry → guarded navigation → identity verification → at most one submission → exact readback → repeated confirmation. Legacy actions retain their proven transaction paths pending gradual migration; their result format is not yet fully unified.

Production extends existing session-local snapshots with version, TTL and identity signature. Construction, advisor and trade observations use the same session-local identity principle: 120-second TTL, changed-identity/version rejection, explicit GUI source and `stable_game_identity=false`. Mutations invalidate uncertain snapshots and never automatically resubmit. Per-line telemetry, complete construction progress and complete trade telemetry remain UNKNOWN; GUI evidence is separately identified.

New domain boundaries are `actions/production_lines.py`, `construction.py`, `politics.py`, `trade.py` and corresponding `executor/*_service.py` / `*_ui.py`. Catalogs provide semantic targets; `non_military_layout.py` owns private fixed-profile layout. The shared pipeline provides precheck, navigation, target verification, one submission, readback, confirmation and cleanup. Cleanup failure cannot retain the action lock or erase already established confirmation.

The Python facade accepts, for example, `operator.execute("build", {"state_id": 64, "building_type": "military_factory"})`. The Agent cannot configure or pass HWND, coordinates, templates or backend objects through action arguments. MCP v0.7.0 exposes 50 tools; the operator explicitly configures the private `--non-military` or `--military` runtime at startup. Unattached GUI tools reject; default telemetry queries remain read-only. Other Agent vendors and a complete Agent Adapter are future integrations, not verified clients in this PoC.

The current backend requires an authorized Computer Use pump. Backend readiness is checked before live client actions; this does not extend action, bridge or watchdog deadlines. Focus loss, F12, HWND/PID/process checks and guarded Esc recovery remain in force. The executor never automatically refocuses. Mod edits, console, effects and direct save edits are prohibited. This session's explicit authorization covers manual Computer Use restoration of an existing minimized window and normal GUI unpause/speed/load; no launch was necessary.

The original calibrated profile remains HOI4 1.19.3, GER 1936 start, base Chinese, Telemetry Mod only, 2560×1080, scale 1.0; Phase 3 legal preparation naturally advanced into 1937. Catalogs deliberately reject uncalibrated targets. Limited Phase 3 remains OFFLINE TESTED / LIVE VERIFIED; its precise evidence is in [the Phase 3 report](PHASE3_NON_MILITARY_EXECUTOR.md).

Phase 4 adds `actions/military.py`, `executor/military_service.py`, `military_ui.py` and `map_resolver.py`. Army, division, front, air-wing and fleet snapshots share a session and use version/TTL/signatures. Land mutations compare all observed division memberships and the army's general; air mutations compare name, type, base, aircraft count, region and missions. All mutations have one submission and two exact readbacks; uncertainty invalidates the affected snapshots. GUI getters navigate and therefore carry non-read-only MCP annotations, even though they do not issue military orders.

Private map calibration covers two GER/POL borders using three city anchors and three independent border segments per target. Normal frontline drawing mode hides moving counters during readback; bounded resampling addresses border-highlight animation without retrying submission. Air region 8 uses three consistent city anchors with at most two pixels of load rounding, followed by the actual GUI region title. A changed camera, unknown identity, damaged anchor or modal blocks the operation. Coordinates never cross the semantic interface.

Observed coverage is explicitly incomplete: three of thirty divisions, the first army and Manstein; two known border markers and the whole-plan switch; one infantry supply tooltip; one of fifteen fighter wings with exactly 80/100 aircraft; one of six naval task forces. Natural reinforcement to 81 aircraft rejects changed identity and has a real-screenshot regression. `get_fleets` identifies 公海舰队 as a task force under 德国海军 with twelve actual ship names, rather than treating it as the parent fleet. Every field states gui/derived/unknown; game unit IDs, full military telemetry and unobserved objects remain UNKNOWN.

`executor/map_profile.py` now records two private MapProfiles with capture dimensions, UI scale, map mode, camera anchors, supported semantic targets and template directory. `GER_1936_2560x1080` preserves the original calibration. `GER_1936_2048x1280` is independently calibrated from real screenshots for offensive lines only, using Amsterdam, Copenhagen and Königsberg. Actual capture dimensions select the exact profile; matching land-mode and anchor templates then validate the calibrated layout. UI scale 1.0 is calibration metadata, not a separately measured runtime field. Unknown dimensions, changed anchors or a different camera reject before submission. No coordinate scaling is used, and other military mutations retain their original resolution guard.

`create_offensive_line(army_id, target)` keeps its semantic schema. Its only new targets are `GER_POL_mainland_Poznan_east` and `GER_POL_mainland_Poland_north_east`; both use the known mainland front with different target regions. The pipeline checks fresh telemetry, session/TTL/signatures, repeated selected-army/front/order observations, exact map anchors and both the active tool icon and drawing caption. It rechecks identity immediately before one guarded native right drag, requires successful release, then performs two exact offensive readbacks. Post-submission failure becomes uncertain and invalidates army/front/order snapshots without retrying. Native release failure aborts readback.

The dedicated `executor/offensive_ui.py` reader verifies army label, originating front, arrow tip and target curve, plus bidirectional scene-mask agreement across its calibrated Poland viewport. Only empty and the two single-order scenes are recognized; the bounded tolerance is two pixels at edges and at most forty residual pixels. Extra or wrong geometry and ambiguous scenes reject. Orders outside this viewport, subpixel or occluded geometry remain UNKNOWN. Orders have GUI_ONLY session-local IDs, snapshot version, 120-second TTL and identity signatures, with derived links to same-version army/front IDs. They are not internal game order IDs. Military telemetry and plan activity in this new reader remain UNKNOWN.
